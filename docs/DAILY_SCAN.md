# 定时盘后观察日报

`scripts.daily_scan` 是生产引擎的运行编排，不是新策略。公开仓库
`geniusgrok/uquant-cli` 的现有日报 workflow 每周一至周五 09:01 UTC
启动，固定为北京时间 17:01；ChatGPT 日报任务读取对应 run 和私有结果，
不再启动另一次计算。生产运行只接受这个执行仓库的 Actions 身份。

## 输入、账户与输出

每次读取当前私有 main，使用锁定的 Python 3.12.13、uv 0.11.33 和 uv.lock。
先核验新浪交易日历覆盖和北京时间收盘时点；休市、日历失效、未收盘均不
生成新信号。运行日期来自当前时钟，不提供任意历史日期的生产覆盖参数。

股票使用现有 `DataStore.refresh_akshare` 的前复权数据，完整刷新生产参考池、
13票观察池以及 `sh000300`、`sh000682` 两个生产指数所需数据。指数使用 AkShare
`index_zh_a_hist` 的原始价格，成交量从手转换为股；逐票展示另取不复权收盘价
及提供方涨跌幅，不把复权价格冒称实际交易所收盘。原始输入写入隔离目录，
不覆盖 `data/frozen`。逐项保存实际日期、行数和失败原因，缺目标日数据即失败。
必要预热、历史前缀、代码和账户校验仍由生产引擎执行，不设置 allow-stale。

固定展示顺序：中际旭创300308、新易盛300502、天孚通信300394、寒武纪688256、
兆易创新603986、拓荆科技688072、联瑞新材688300、鼎龙股份300054、中科飞测688361、
雅克科技002409、源杰科技688498、华海清科688120、东山精密002384。

没有用户指定的完整实盘快照，本任务建立且只建立一次默认现金的连续观察账户，
明确标为非实盘、不执行模式。不模拟或伪造任何成交，保留订单意图和风险状态；
因此它不代表已执行策略的投资组合，也不能解释为用户账户专属建议。
这不是 Future Holdout，不追加其正式 session 或分数。

一次 `ProductionEngine.decide` 同时产出机会、Base Risk、Risk Sentinel、
最终分配证据、目标和订单意图。JSON 保留完整决策，Markdown 先展示13票与对比，
再附生产系统原始中文日报；非有限的诊断值明确保存为 null。没有对应输出的
字段为“未提供”，没有订单不推断为 HOLD 或允许买入。风险观察覆盖非 READY
时报告为 PARTIAL，不能宣称完整风险资料已经就绪。

前一交易日结果须通过清单哈希、观察账户身份、经济代码与配置指纹校验。
新账户、缺失、跨日缺口或不同经济版本不猜测“无变化”，不自动回算历史。
同一经济指纹下仅源码 SHA 改变也单独披露。缺字段列为不可比较。

## 私有存储与激活要求

唯一报告目标是私有 `ychenracing/uquant` 的 `uquant-daily-reports` 分支。
每次写入前核验仓库仍为 private。`UQUANT_READ_TOKEN` 只读取私有源码，
不会被尝试用于写入。公开 runner 需要另有已配置、明确授权的私有报告写入
凭据 `UQUANT_REPORT_WRITE_TOKEN`。本次代码不会创建 Secret、读取其值或扩权。
没有写入通道即明确失败，不能把公开 Artifact 或输出完整日志作为替代。
不要把这个缺口误记为已完成端到端部署。

全部私有源码、运行输出和 uv 缓存仅在临时 runner 工作区；公开日志只打印
白名单状态。中文报告、账户、输入及受控原始日志通过原生 Git 保存到私有分支，
不用模型中转大文件；写后实际读取远端 blob 字节，核验逐字节、长度、SHA-256
及 Git object ID。复制期间发生变化的日志拒绝归档。

主要路径：
- `latest.json`：最后一次成功发布的结构化结果位置及文件校验清单。
- `reports/YYYY-MM-DD/`：report.md、result.json、decision.json、运行前后账户及日历。
- `inputs/`：最后发布版本的完整行情和逐票输入审计；历史版本沿该分支 Git 提交恢复。
- `claims/YYYY-MM-DD.json`：调用生产决策前已持久化的日期占用记录。
- `failures/YYYY-MM-DD-RUN/`：未发布为有效决策的失败原件与状态。
- `runs/RUN-ATTEMPT/`：bootstrap、scan、cloud_guard 原始日志及保存清单。

## 幂等、事务与恢复

下载、校验输入后，先正常推送并回读日期 claim，只有一个写者可以成功。
然后才调用一次决策。在途、未知或失败后未对账的 claim 阻止重新决策；
不能通过换 run 名、撤并发锁或每天重置账户解除。已有同日有效结果只回读复用，
即使 main 有新提交也不把旧结果冒称新源码运行。

报告、完整决策、账户和输入在一个 Git commit/ref 更新中发布。push 超时或
响应未知先读取远端，不重复 push。冲突、账户历史前缀变化（包括提供方前复权
历史修订）、代码指纹变化和漏交易日必须保留证据后人工核对，禁止清空状态。
生产调用后的失败 claim 默认需要恢复核验，不自动重算；已有决策原件可用于
完成文件发布，但不是重新运行引擎的许可。

故障后先读对应 run jobs、私有 claim/latest/failures，区分计算失败、发布未确认
与单独日志归档失败。`computed_at` 是计算完成时间，不冒充整个 Actions Job
完成时间；任务交付时另从 jobs API 读取真实启动/完成时间。尚未完成写未完成。
私有写入全部受阻时 runner 临时原件仍可能随机器回收丢失，不能声称已持久保存。

## 验证范围

`tests/test_daily_scan.py` 检查日历、13票投影、缺失比较、意图仓位变化、真实
本地 Git 竞争写入/远端字节回读、失败原件及账户不被误发布；私有 Actions
另用仓库冻结夹具运行两个连续生产决策及重复调用保护。夹具验证不是当天行情
运行或经济回测验收。不修改经济决策模块，不重跑完整 Absolute 矩阵。
