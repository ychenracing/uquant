# 工程质量与行为契约

本文定义仓库当前采用的质量标准。质量改进必须提高可读性、可维护性和故障可诊断性，同时保持策略决策与回测结果不变。

## 行为边界

以下内容属于不可改变的策略行为：

- 特征计算、行情识别、风险状态转换和候选排序；
- 目标仓位、集中度、资金预算、交易门槛和订单执行顺序；
- 默认参数、账户状态含义、数据时点和回测执行口径；
- 绩效门槛、冻结数据、证据摘要和失败关闭规则。

质量工作可以补充说明、改善错误信息、消除确定的代码缺陷和加强不变量校验。任何可能改变信号、仓位、订单、成交或指标的建议，只有在独立策略任务中取得新的经济性证据后才能实施。

## 自动质量门

| 检查 | 约束 |
|---|---|
| Ruff | 检查语法、导入、常见缺陷、简化和性能规则 |
| strict mypy | 对生产包和研究工具执行严格类型检查 |
| pytest | 覆盖单元、集成、性质、账户状态和失败路径 |
| 分支覆盖率 | `uquant` 的分支覆盖率不得低于 85% |
| compileall | 所有 Python 模块必须能够编译 |
| 构建检查 | wheel 和 sdist 必须可重复构建 |
| Bandit | 静态安全检查不得出现未处理问题 |
| pip-audit | 生产依赖不得包含已知未处理漏洞 |
| 数据完整性 | 冻结文件、清单和 SHA-256 必须互相一致 |
| 经济性回归 | 冻结场景中的财富、回撤、订单和换手约束必须通过 |

上述门禁均为阻断条件，不能用另一项检查的成功抵消失败。

## 注释标准

- 模块说明负责交代职责、输入输出和关键约束。
- 公共类与函数说明调用契约、返回值、副作用和重要异常。
- 行内注释解释状态机、不变量、时点约束和非显然的业务原因。
- 不逐行翻译代码，不重复类型签名，不保留时间线式开发叙述。
- 注释只描述当前系统，不引用外部项目，也不记录已经被替代的实现。

## 文档结构

README 提供快速开始和文档导航；其余文档各自保持单一职责：

| 文档 | 内容 |
|---|---|
| `ARCHITECTURE.md` | 模块边界、决策链路、状态和数据流 |
| `STRATEGY.md` | 信号、组合构建、风险控制、适用范围和局限 |
| `CONFIGURATION.md` | 参数含义、相互约束和调节风险 |
| `OPERATIONS.md` | 每日运行、账户维护、故障处理和安全检查 |
| `PERFORMANCE.md` | 回测口径、指标解释、证据边界和结果复现 |
| `DEVELOPMENT.md` | 开发环境、测试命令和提交检查清单 |
| `QUALITY.md` | 本文所列的质量与行为保持契约 |

文档应足以指导使用和维护，但避免重复粘贴完整参数表、源码流程或测试实现。

## 审查与行为保持

每轮质量工作按照以下顺序执行：

1. 在修改前保存测试、静态检查和冻结回测证据。
2. 小批量修改注释、文档或经验证的健壮性问题。
3. 审查修改是否触及策略所有者、参数默认值或交易路径。
4. 运行相关测试，再运行完整质量门。
5. 对比修改前后的冻结指标与关键输出摘要，要求逐项一致。
6. 再次审查完整差异；若发现有效问题，修复后重新执行本流程。

不得通过改写基线、放宽断言、删除失败场景或改变统计口径制造通过结果。无法证明行为等价的改动不属于本质量任务。

## 维护规则

- 配置、代码、日报和文档必须对同一行为使用一致术语。
- 新参数必须有范围校验、失败边界测试和文档说明。
- 新状态必须进入账户数据契约、序列化摘要和恢复测试。
- 研究模块不得成为第二个生产决策入口，也不得被生产包反向依赖。
- 生产决策必须继续由 `ProductionEngine.decide()` 驱动，目标权重必须继续由唯一组合分配器生成。
- 数据或证据缺失、摘要漂移和账户不一致必须失败关闭。
